## Главная проблема — данных для экранов нет

Всё, что админ должен сделать, сейчас записано прозой в `clients/<client>/NEXT.md`, отчётах и журналах.
Интерфейсу нечего показывать. Поэтому первым шагом — два машиночитаемых файла, которые пишут агенты
и читает интерфейс. Это полезно и без интерфейса: облачная задача и чат видят один и тот же список.

### 1. `core/setup/requirements.yaml` — что нужно для работы (один раз на систему и на клиента)

```yaml
- id: openai-key
  scope: system            # system | client
  module: geo
  kind: secret             # secret | account | access | data | decision
  title: Ключ OpenAI с балансом
  unlocks: замер видимости в ChatGPT
  where: секреты репозитория (OPENAI_API_KEY) или .env; в облаке — окружение seo-agents
  how: [platform.openai.com → API keys, Billing → пополнить на $10–20]
  cost: до $5 в неделю
  check: secret:OPENAI_API_KEY   # как интерфейс понимает «готово»
  required: false
```

`check` — автоматическая проверка, без ручных галочек там, где это возможно:
- `secret:NAME` — есть ли секрет с таким именем в репозитории (GitHub API отдаёт только имена, не значения);
- `field:client.yaml:gsc_site` — поле заполнено;
- `file:clients/<c>/geo/queries.csv:approved>=30` — данные есть;
- `run:geo-weekly` — последний прогон Actions прошёл;
- `manual` — только отметка админа (например, «Google Business Profile подтверждён»).

### 2. `clients/<client>/admin/tasks.yaml` — очередь действий для админа и владельца сайта

```yaml
- id: 2026-11-07-openai-balance
  who: admin              # admin | owner (владелец бизнеса клиента)
  title: Пополнить баланс OpenAI
  why: без него замер ChatGPT не идёт (credit_balance_exhausted)
  blocks: [geo-weekly]
  steps: [platform.openai.com → Settings → Billing → Add credits]
  draft: null             # ссылка на готовый текст, например geo/offsite/queue/olx.md
  priority: 1
  status: open            # open | done | skipped
  created: 2026-11-07
  source: оркестратор
  done_at: null
  note: null
```

Агенты добавляют задачи сюда вместо прозы в NEXT.md (в NEXT.md остаётся только «на чём остановились»).
Админ в интерфейсе нажимает «Сделано» / «Пропустить» / пишет ответ — это коммит в репозиторий и строка в журнале.
Вопросы владельцу («цены?», «срок под заказ?») — тоже задачи `kind: decision` с полем ответа.

## Экраны (новые — первыми)

1. **Перед началом** — чек-лист из `requirements.yaml`: системные и по клиенту, зелёное/красное,
   что откроется после выполнения, сколько стоит, пошаговая инструкция. Наверху — «готово N из M».
2. **Действия** — очередь из `tasks.yaml` по всем клиентам: сначала то, что блокирует работу;
   фильтр admin / owner; кнопки «Сделано», «Пропустить», «Ответить»; для внешних площадок — готовый текст
   с кнопкой «Скопировать».
3. **Ввод ключей** — форма, которая кладёт ключ сразу в секреты GitHub репозитория (шифрование на стороне
   GitHub API, интерфейс ключ не хранит и не показывает). Показывает только «задан / не задан».
4. **Новый клиент** — анкета `client.yaml` с проверкой по схеме, затем список требований по этому клиенту.
5. Дальше — экраны Фазы 5: клиенты, обзор клиента (позиции, показы, GEO-видимость против baseline),
   очередь одобрения, отчёты, журнал, настройки.
