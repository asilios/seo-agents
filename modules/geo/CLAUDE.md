# Модуль GEO (Generative Engine Optimization)

Цель: чтобы ChatGPT, Perplexity, Gemini и Claude называли и рекомендовали компанию клиента, когда
пользователи спрашивают про его нишу. Модуль универсальный: всё про нишу, языки, конкурентов и регион —
только в `clients/<client>/geo/profile.yaml`. В агентах, скриптах и шаблонах слов про конкретную нишу нет;
примеры — из разных ниш. Архитектура и решения владельца: `docs/geo-architecture.md`.

## Что можно утверждать

- Метрика (AI Visibility Score и др.) — **оценка по ответам API с веб-поиском**, а не то, что увидит каждый
  пользователь в приложении. Ответы случайны: каждый вопрос гоняется 3–5 раз.
- Выводы «выросли / упали» — только если доверительные интервалы недель не пересекаются; иначе «в пределах шума».
- Числа — только из `geo/observations.jsonl`, `geo/metrics/` и ответов скриптов. Нет данных — так и писать.
- Частотность и объём спроса на вопросы к ИИ неизвестны; приоритет вопроса — оценка, а не цифра.

## Агенты (`.claude/agents/`)

| Агент | Что делает | Когда |
|---|---|---|
| `geo-query-mapper` | 30–100 вопросов к ИИ по интентам | при подключении и раз в квартал |
| `geo-citation-analyst` | приоритетный список площадок по цитированиям | еженедельно, после замера (Фаза 3) |
| `geo-onsite-optimizer` | answer-first тексты, FAQ, JSON-LD, llms.txt, согласованность данных (Фаза 4) | после замера |
| `geo-offsite-agent` | черновики заявок, PR, запросов отзывов — только в очередь (Фаза 5, общий с `local-offpage`) | после анализа |

Мониторинг — **скрипт**, не агент: geo_monitor.py + geo_providers.py + geo_parse.py в `modules/geo/scripts/` (Фаза 2: план по умолчанию, вызовы только с `--execute`). Прогон идёт через GitHub Actions
(`.github/workflows/geo-weekly.yml`, Фаза 6) с секретами репозитория: в облачной задаче Claude ключей нет.

## Данные клиента (`clients/<client>/geo/`)

```
profile.yaml          бренд и синонимы, конкуренты, языки, регионы, модели, прогонов на вопрос, бюджет
queries.csv           id,text,lang,intent,region,priority,status   (pending → approved → retired)
observations.jsonl    один ответ ИИ = одна строка, без полного текста (в git, источник правды)
runs/<YYYY-Www>/      сырые ответы (в .gitignore)
geo.db                SQLite — производная от observations.jsonl (в .gitignore)
metrics/              <YYYY-Www>.json и latest.json
citations/            <YYYY-Www>.csv и .md
changes/pending|approved|applied/   правки сайта (жизненный цикл как в SEO)
offsite/queue/        задачи для владельца: pending → approved → done
log.md                журнал: YYYY-MM-DD | агент | что сделано | файлы
```

## Жёсткие правила модуля

1. **Ничего не отправляется наружу автоматически.** Заявки в каталоги, письма, формы, отзывы, PR — только
   черновик в `offsite/queue/` со статусом `pending`. Отправляет владелец.
2. **Бюджет — жёсткий предел.** `budget_usd_per_week` из профиля. Скрипт до старта печатает число вызовов и
   верхнюю оценку; без значения бюджета или при превышении не запускается.
3. **Ключи только в `.env` и секретах репозитория** (`OPENAI_API_KEY`, `PERPLEXITY_API_KEY`, `GEMINI_API_KEY`,
   `ANTHROPIC_API_KEY`). Не просить ключи в чате, не печатать, не коммитить.
4. Вопросы к ИИ пишутся так, как их задал бы человек, **без названия клиента** (кроме контрольных брендовых).
5. Запрещённые обещания клиента (`forbidden_claims` в `client.yaml`) не попадают в тексты для сайта и внешних площадок.
6. Правки сайта идут общим путём SEO: ветка, проверки, слияние по правилу 1 `core/CLAUDE.md`.
   Цены, сроки, обещания, контакты — только с владельцем.
7. `profile.yaml` не менять без запроса владельца; найденных конкурентов — предлагать в отчёте.

## Проверка данных

`python modules/geo/scripts/validate_geo.py --client <client>` — профиль по схеме
`core/schemas/geo-profile.schema.json`, формат и уникальность `queries.csv`.

## Циклы

- **Подключение клиента** (`/geo-map <client>`): заполнить `geo/profile.yaml` → `geo-query-mapper` → список в `pending` →
  владелец утверждает (`status: approved`) → первый замер (Фаза 2).
- **Еженедельно** (`/geo-weekly <client>`, с Фазы 6): монитор → агрегация → `geo-citation-analyst` →
  `geo-onsite-optimizer` → `geo-offsite-agent`.
