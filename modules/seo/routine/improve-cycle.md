# Цикл постоянного улучшения сайта клиента

Эту инструкцию выполняет запуск по расписанию (облачная задача / cron) и оркестратор в чате.
Цель владельца: сайт клиента — на первой странице поиска, в идеале в топе. Успех меряется
позициями, показами и кликами, а не количеством закрытых пунктов аудита.

Жёсткие правила из `core/CLAUDE.md` действуют всегда. Публикуем сами (разрешено владельцем 2026-11-02),
но только после всех проверок из правила 1 `core/CLAUDE.md` (список проверок — `modules/seo/CLAUDE.md`); цены, сроки, обещания покупателям — только с владельцем.

## Каждый запуск (раз в неделю)

1. **Синхронизация.** `git pull`. Прочитать `clients/<client>/NEXT.md`, хвост `clients/<client>/seo/log.md`,
   последний `seo/audits/*.md`, `seo/audits/issues.json`.
   Пути: `client.yaml`, `NEXT.md`, `reports/` — в `clients/<client>/`; остальное SEO — в `clients/<client>/seo/`.

2. **Замер — что изменилось с прошлого раза.**
   - GSC (если есть ключ): `python core/scripts/gsc.py --site <gsc_site> --days 28 --out clients/<client>/seo/data/gsc-YYYY-MM-DD.csv`
     и сравнение с прошлой выгрузкой (`--compare`). Проверка индексации ключевых URL (URL Inspection).
     Затем `python modules/seo/scripts/keyword_volumes.py gsc --client <client>` и `... score --client <client>`:
     реальные запросы сайта, «быстрые победы» на позициях 8–30 и запросы GSC вне ядра — в `seo/keywords/priorities.md`.
     Запросы вне ядра с показами — кандидаты в кластеры для `keyword-strategist`. Нет показов — так и писать.
   - Срез выдачи по 10–15 главным запросам из `seo/keywords/clusters.md` (поиск с location Uzbekistan) →
     `seo/data/serp-YYYY-MM-DD.md`, сравнение позиций с прошлым срезом.
   - Аудит: субагент `auditor` (краул, ошибки, регрессии).

3. **Анализ — что сейчас сильнее всего тормозит рост.** Ранжировать гипотезы по
   (ожидаемый прирост показов/кликов) × (уверенность) / (трудозатраты). Типичные источники:
   - страницы, которые не в индексе (особенно коммерческие);
   - запросы на позициях 8–30 в GSC — их дожимать в первую очередь (title/H1/текст/ссылки);
   - страницы с показами и низким CTR — переписать title/description;
   - запросы из `clusters.md` без целевой страницы — новая страница/статья;
   - конкуренты из выдачи, которые обходят: чем именно (цены, отдельные страницы, контент);
   - технические регрессии из аудита.
   Не повторять то, что уже сделано (`seo/changes/applied/`) и не дало эффекта, без новой причины.

4. **Действие — 1–3 самых сильных улучшения за запуск.**
   - Тексты/мета/статьи готовят субагенты (`onpage-optimizer`, `content-writer`) → `seo/changes/pending/`;
     оркестратор проверяет их и сам переносит в `approved/`.
   - Внести в код сайта веткой `seo-auto-YYYY-MM-DD`, пройти все проверки из правила 1 `core/CLAUDE.md` (список проверок — `modules/seo/CLAUDE.md`),
     пересобрать `forma-3d-source.tar.gz`, слить в `main`, проверить живой сайт, перенести правки в `applied/`.
     Проверка не прошла — не сливать, ветку оставить, написать в отчёте почему.
   - Всё, что требует решения владельца (цены, сроки, обещания, удаление разделов) — вопросом в отчёте.

5. **Отчёт владельцу** → `clients/<client>/reports/weekly-YYYY-MM-DD.md`, коротко:
   что изменилось в цифрах (позиции, показы, клики, индексация) → что выложено (ссылки на коммиты) →
   что нужно от владельца (вопросы, действия вне сайта: Google Business Profile, отзывы, ссылки, цены).

6. **Журнал и синхронизация.** Строки в `seo/log.md`, обновить `NEXT.md`, `git add -A`, коммит на русском, `git push`.

## Чего не делать
- Не выдумывать цифры: только из GSC, краула, выдачи. Нет данных — так и написать.
- Не трогать `seo/baseline.md`.
- Не сливать в main без всех проверок; не публиковать цены, сроки, обещания без владельца.
- Не делать больше 3 крупных изменений за запуск: иначе непонятно, что дало эффект.
